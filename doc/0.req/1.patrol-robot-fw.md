# ch1.巡逻机器人项目直接用 ROS2 + ROS2_Control+ ROS2_Nav2的实现架构？

## sec.1 结论先说
**完全可以实现你的智能巡逻预警机器人核心需求，而且比直接上Autoware轻量很多，开发、部署、调参难度大幅下降。**
Autoware是面向**自动驾驶车辆（汽车级别，带高精地图、感知、预测、决策）**的重型框架；你的项目是**厂区/道路小型巡逻机器人**，ROS2 + ROS2 Control + Nav2 刚好匹配。

> 你项目原始需求回顾：自动巡逻、定点值守、自主避障、低电量返航、远程调度、匝道可人工接管、证据留存。
> 硬件：客户提供小车硬件，你做小车端嵌入式/ROS软件。

## sec.2各需求对应的组件匹配
### sec.2.1. 底盘运动、电机驱动 → ROS2 Control
- 负责：速度闭环、里程计、电机扭矩/速度控制、底盘状态上报
- 写简单的硬件接口插件（`hardware_interface`）对接你底层嵌入式（小车电机、IMU）
- 输出 /cmd_vel，接收编码器、IMU反馈
- 支持模式切换：自动模式 / 人工遥控接管（正好匹配匝道人工接管需求）

### sec.2.2. 自主巡逻、定点值守、导航、避障、低电量返航 → Nav2
Nav2自带全部能力：
1. **巡逻路线**：设置多个路点(waypoint)，顺序巡线，循环巡逻
2. **定点值守**：到达目标点后原地等待一段时间，再继续下一个点
3. **自主避障**：集成代价地图，激光/雷达/深度相机数据做障碍物检测，动态绕障
4. **返航逻辑**：低电量触发导航目标点设为充电基站，自动返航
5. 支持外部上位机/云下发目标点、任务指令（客户上位机、云平台来调度）

### sec.2.3. 感知（障碍物检测）
- 基础避障：2D激光雷达 → Nav2 原生支持
- 复杂场景（行人、物体分类预警）：可额外加YOLO等，作为独立ROS2节点输出告警信息，上报给客户云/上位机
> 预警业务逻辑（发现异常触发告警）你自己写简单ROS2节点，把告警消息发给客户上位机接口。

### sec.2.4. 定位方案（你前面关心的RTK）
Nav2支持多种定位融合：
- RTK-GNSS + IMU + 里程计 融合（`robot_localization`，EKF/UKF）
- 适合室外道路/厂区巡逻场景，不需要高精地图（对比Autoware）

### sec.2.5. 远程调度 & 人工接管
- 人工接管：上位机下发遥控速度指令，软件层面做模式切换：自动模式下Nav2输出cmd_vel；人工模式直接透传上位机cmd_vel，Nav2暂停规划。
- 状态上报：机器人位置、电量、告警、传感器状态，封装消息发给客户云/上位机（按客户提供通信协议对接）

### sec.2.6. 证据留存
ROS2 自带 `rosbag`，录制传感器、定位、告警、运动数据；你写简单节点自动按任务分段保存bag包，满足证据留存。

## sec.3 ✅ 对比：ROS2+Nav2  vs Autoware
| 维度 | ROS2+ROS2Control+Nav2 | Autoware |
|---|---|---|
| 体量 | 轻，编译快，依赖少 | 重型，依赖爆炸，部署痛苦（你已经体会） |
| 适用场景 | 室外巡检机器人、AGV、巡逻小车 | 自动驾驶乘用车 |
| 地图 | 可以用2D栅格地图 + RTK，构建简单 | 需要高精矢量地图，建图成本高 |
| 开发难度 | 低，Nav2原生waypoint巡逻、返航 | 复杂，大量模块需要适配、调参 |
| 硬件需求 | 普通工控板即可 | 高，需要强GPU跑感知预测 |
| 你的项目适配度 | ⭐⭐⭐⭐⭐ | ⭐⭐ |

## sec.4 ⚠️ 需要自己开发的部分（也就是你外包报价里嵌入式/ROS软件范围）
1. ROS2 Control hardware_interface 驱动层：对接小车电机、编码器、IMU（嵌入式 ↔ ROS2通信）
2. 任务调度节点：管理巡逻任务、定点停留、低电量判断、触发返航、模式切换（自动/人工接管）
3. 传感器数据接入：雷达、电量检测模块
4. 对外通信节点：和客户上位机/云平台通信，按协议上报状态、接收任务指令
5. 告警业务节点：障碍物/异常检测后的告警封装、rosbag自动录制管理

## sec.5 边界提醒（贴合你之前报价文档）
> 客户负责上位机、云平台；你只做机器人端ROS2软件+底层嵌入式。
> Nav2、ROS2 Control 是开源组件，**你的工作量是集成、适配硬件、业务逻辑开发，不是重写导航算法**。

## sec.6 什么时候才需要上Autoware？
只有当你需要：矢量高精地图、车道线感知、车辆行为预测、交通信号灯识别、复杂路口自动驾驶，才值得踩Autoware的坑。
你的道路巡逻机器人，**完全没必要引入Autoware，徒增部署成本和项目风险**。

# ch3.智能巡逻机器人（ROS2 + ROS2 Control + Nav2）软件实现步骤
> 项目边界重申：客户提供硬件、上位机&云平台；我方负责小车端嵌入式固件 + ROS2软件，客户提供通信协议文档。

## 阶段0：前期准备（需求&环境，约3工作日）
1. 对接客户，确认硬件清单：底盘电机、编码器、IMU、RTK、激光雷达、电池采集模块；拿到硬件电气接口、通信协议。
2. 确认**上位机 ↔ 机器人**通信协议（消息格式、心跳、任务下发、告警上报、遥控指令），输出接口协议评审文档。
3. 开发环境搭建：Ubuntu24.04 + ROS2 Jazzy；安装Nav2、ros2_control、robot_localization、rqt/rviz。
4. 建立代码仓库，规划目录结构：嵌入式固件仓库、ROS2功能包仓库。

## 阶段1：底层嵌入式固件开发（约8工作日）
> 对应架构图【小车嵌入式固件】模块
1. 底层驱动开发：电机驱动、编码器采集、IMU数据读取、电池电压/电量采集。
2. 封装数据接口：向上输出轮式里程计、IMU、电池状态；接收速度指令控制电机。

   - 读：编码器里程、IMU、电池状态
   - 写：下发目标速度指令

3. 启动controller_manager，加载diff_drive底盘控制器。
4. 单独闭环测试：rviz下发`/cmd_vel`，底盘跟随运动，校验里程计精度。

1. 激光雷达驱动部署，发布`/scan`话题，在RViz验证点云。
2. RTK驱动部署，发布GPS位姿消息。
3. 配置`robot_localization` EKF融合：轮式里程计 + IMU + RTK，输出融合后`/odom`、`/pose`。
4. 室外定点测试定位：验证静止漂移、移动轨迹精度，调EKF参数。

## 阶段4：Nav2导航栈部署与基础导航调参（约8工作日）
> 对应 Nav2 导航栈
1. 部署Nav2全套包，编写nav2启动文件、yaml参数。
2. 室外建图：使用SLAM（如lidarslam）建立厂区2D栅格地图。
3. Nav2基础测试：单点目标导航，测试全局规划、局部避障、代价地图。
4. 参数调优：避障膨胀层、速度限制、机器人外形尺寸，保证障碍物可绕行。
5. Waypoint序列测试：Nav2 FollowWaypoints执行多点巡逻，到达路点支持停留等待。

## 阶段5：自研业务节点开发（核心业务，约10工作日）
> 通信协议适配节点 + 任务调度节点 + 告警管理节点
1. **通信协议适配节点**
    - 实现和客户上位机/云平台双向通信（TCP/Websocket按客户协议）
    - 接收指令：启动巡逻、停止、定点任务、遥控指令；上报机器人状态、位置、告警、电量。
2. **任务调度节点（核心）**
    - 任务管理：加载路点列表，顺序巡逻、循环巡逻、定点停留。
    - 低电量逻辑：读取电池状态，低于阈值自动触发返航（设置充电基站为nav目标点）。
    - **模式仲裁逻辑**：
      - 自动模式：任务调度输出目标路点，Nav2自主规划，输出速度指令给ros2_control

    - 自动管理rosbag录制：任务开始自动录包、任务结束停止，按时间/任务ID命名保存，满足证据留存。

# ch4. ✅ 整套传感器梳理 + 定位/感知拆分 + SLAM选型（匹配你的硬件清单）

> 
> 硬件清单回顾：
> **定位传感器**：RTK + IMU + 轮速里程计融合（EKF，目标≤10cm）
> **感知传感器**：100m 2D激光雷达、毫米波雷达、全景1080p@25fps相机、超声波补盲
> 场景：城市道路巡逻机器人，Nav2做自主巡逻导航

## 一、定位系统架构【重点】

### 定位核心：`robot_localization ekf_node`

输入：RTK、IMU、轮速里程计，输出平滑全局位姿，目标精度≤10cm

- RTK固定解：提供全局绝对坐标（UTM），抑制长时间漂移；高楼/树荫遮挡时会降级为浮点解/单点解，此时**不能当做全局真值**
- IMU：补偿机器人俯仰/横滚、短时间RTK丢星时维持姿态
- 轮速里程计：提供短时间连续相对运动观测

> 
> ⚠️ 关键逻辑：
> **这套EKF融合已经能输出全局位姿，不再依赖激光SLAM做全局定位！**
> 激光SLAM角色发生改变：不再负责解决全局漂移/回环，只做两件事：
> 
> 
> 1. 构建环境2D栅格地图，用于Nav2的**路径规划**（禁入区域、路沿、静态障碍物）
> 2. 局部位姿修正：RTK跳变/短暂失锁时，利用激光匹配（地图先验）小幅修正EKF位姿，提升鲁棒性

### SLAM包选型最终结论

**slam_toolbox，online_async建图，上线后用localization模式**

- 建图阶段：机器人沿巡逻路线跑一遍，EKF输出的RTK融合位姿作为**外部位姿先验**喂入slam_toolbox；**关闭slam_toolbox原生全局回环**（避免长直道路激光几何误回环，覆盖RTK全局约束）。激光只做局部扫描匹配，生成静态环境栅格地图+位姿图。
- 上线巡逻阶段：slam_toolbox进入`localization`定位模式，加载建好的位姿图；EKF(RTK+IMU+轮速)为主定位源，激光匹配作为辅助观测，用来抑制RTK小跳变。
- lifelong模式可选：如果道路环境经常变化（路边临时停车），启用lifelong持续更新地图，剔除动态物体。

> 
> Cartographer备选：如果路面起伏大，子图局部匹配更稳；但缺少slam_toolbox强大的lifelong地图更新能力，动态场景维护麻烦。
> ❌ rtabmap不推荐：全景相机室外光照波动大，视觉特征不稳定，不需要引入视觉回环增加复杂度。

## 二、感知模块分工（各传感器职责划分）

| 传感器 | 量程 | 核心职责 | 适用场景 | 局限 |
| --- | --- | --- | --- | --- |
| 100m 2D激光雷达 | 100m | 1. 构建SLAM栅格地图，供Nav2规划   2. 检测静态障碍物（路沿、隔离墩）   3. 局部激光点云匹配辅助定位 | 远距离静态物体，轮廓清晰 | 无法识别物体类别；雨天点云噪声大；无法检测低矮薄物体 |
| 毫米波雷达 | 几十~上百米 | 动态目标检测（车辆、行人），测速测距，恶劣天气（雨/雾）鲁棒 | 跟踪移动车辆行人 | 角分辨率差，横向定位精度低；无法区分静态障碍物 |
| 全景相机1080p/25fps | 视觉 | 1. 场景分类：人行道、车道、红绿灯、交通标识   2. 违规事件识别（占道、占道停车、垃圾）   3. 记录巡逻视频取证 | 识别物体类别、语义信息 | 强光、逆光、阴影、夜间效果差；无法直接测距 |
| 超声波补盲 | 近距离，几米 | 车身近距离低矮盲区补盲，防擦碰 | 近距离低矮障碍物（路桩、台阶） | 测距短，易受空气、噪声干扰 |

### 感知融合思路

- 激光 + 毫米波雷达融合：**动静障碍物分离**
  - 激光获取障碍物轮廓、位置；毫米波判断物体是否运动、速度；
  - 静态障碍物 → 送入Nav2代价地图（inflation层，用于避障）
  - 动态目标（车辆行人） → 预测运动，做动态避障，不写入静态地图
- 全景相机：独立语义识别/取证，**不参与定位**（室外光照不稳定，视觉定位容易翻车）
- 超声波：近距离安全防护，紧急停止触发

## 三、整套系统数据流

```
传感器采集 → 时间同步(PPS优先)
├─ RTK+IMU+轮速 → robot_localization(EKF) → 全局平滑位姿
├─ 100m激光雷达 → slam_toolbox
│                 ├─建图阶段：生成静态环境地图
│                 └─上线阶段：局部点云匹配，辅助修正EKF位姿
├─激光+毫米波雷达 → 障碍物融合模块 → 动态/静态障碍物
│                                        ↓
├─全景相机 → 语义识别、事件抓拍、录像取证
                                          ↓
                         Nav2（规划+控制）←代价地图(静态地图+实时障碍物)
```

## 四、工程重点风险点（城市道路场景）

1. **时间同步**：所有传感器统一时间基准，RTK的PPS信号做硬件同步。软件时间同步会带来几十ms误差，激光/毫米波融合直接错位。
2. **RTK状态校验**：只有`固定解`才送入EKF；浮点解/单点解时降低RTK权重，依靠IMU+轮速+激光维持定位。城市峡谷（高楼边）RTK容易跳点，必须做异常值剔除。
3. **动态物体隔离**：建图时要尽量减少行人、车辆进入地图，否则地图污染；slam_toolbox的lifelong就是用来慢慢清理这类动态噪点。
4. 多传感器外参标定：
   - 激光、毫米波、全景相机，都需要和机器人本体（base_link）做外参标定，统一坐标系。
5. 代价地图分层设计（Nav2）
   - 静态层：slam_toolbox输出的地图（道路、路沿、建筑）
   - 障碍物层：激光+毫米波融合实时障碍物
   - 膨胀层：安全缓冲区域

## 五、可选的两套备选方案对比

### 方案1（推荐，上面这套）

EKF(RTK+IMU+轮速)为主定位源 + slam_toolbox做地图+局部辅助定位，激光+毫米波做障碍物感知，全景相机做语义取证。
✅ 优势：全局位姿稳定，长直道路无回环歧义；支持动态环境地图更新；Nav2原生适配。

### 方案2（简化方案）

完全不用激光SLAM，EKF(RTK+IMU+轮速)直接作为定位源；激光+毫米波只负责障碍物检测，静态地图提前人工标注（osm地图）。
✅ 优点：架构简单，省去SLAM调参；
❌ 缺点：OSM地图精度差，路沿、隔离墩等局部几何缺失，避障容易失效；无法感知道路现场临时新增障碍物。
